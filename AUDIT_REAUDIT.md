# ArtWalk LA — Re-Audit (post-remediation)

*Produced by 11 auditors with adversarial verification of all P0/P1 items, 2026-06-02, re-run after the remediation pass.*

## Executive summary

The app is in genuinely good, near-shippable shape. After the remediation pass, the **iOS App Store binary itself is clean and uploadable**: the shipping data layer (both `index.html` and the byte-identical `www/` mirror) decodes to strictly facts-only records (108 artists, 52 buildings) with zero bio/photo/profile fields; no copyrighted map artwork or scraped photos exist in any shipping path; `Info.plist`, `PrivacyInfo.xcprivacy`, versioning, and the alpha-free 1024 icon are all valid; and the core app (map render, geolocation projection, favorites, gestures, accessibility) is robust and defensively coded. The two adversarially-confirmed P1s are **not** binary defects — they live in git history and on the web/PWA delivery path.

**RESOLVED by the remediation pass (verified):**
- **HANDOFF "known bugs" largely fixed** — `1910 N. Main` now correctly in the NW corner (`index.html` POSITIONS, x:139/y:64); 8 of 9 previously-missing buildings (606, 608, 614, 616, 674, 678, 688, 694) now present; `?overlay=1` calibration mode removed.
- **Content-rights strip is clean** — `artists.json` is facts-only (dropped images/bio/profile_url/category_original); all copyrighted source assets are quarantined in gitignored `_archive/`; no copyrighted blob is git-tracked at HEAD or present in `www/`/`ios public/`.
- **Native config fixes landed** — `Info.plist` `ITSAppUsesNonExemptEncryption=false` present; `UIRequiredDeviceCapabilities` is arm64-only (armv7 removed); honest `NSLocationWhenInUse` string.
- **Scraper removal complete** — image-scraper npm scripts, script files, and the tesseract dependency are gone from `package.json`; ~12 dead scripts archived to gitignored `_archive/legacy/`.
- **Accessibility hardening landed** — per-building `role=button`/`tabindex`/`aria-label`/keydown; sheet + About focus capture/restore with Tab-trap; global Escape; `user-scalable=no` removed (WCAG 1.4.4 escape hatch restored); 44px tap targets.
- **Security hardening landed** — `safeUrl()` http(s) allowlist on data-derived `<a href>`; `fuzzyHighlight` escapes per-character; "Near me" now respects active filters.

**REMAINS open (top risks):**
1. **P1 — Copyrighted content in public git history.** The official map (`Map.jpg`, `map_greyscale.jpg`, `bw map.jpg`, `template.svg`, `image00001.jpeg`) + 197 scraped artist photos are still reachable in the 61 MB `.git`, and `HEAD == origin/main` on the **public** `github.com/Mattkillsyou/ArtWalk.git` (verified). The working-tree delete did not rewrite history. **Human-only legal gate.**
2. **P1 — SW cache version `studiomap-shell-v1` never bumped** (`sw.js:9`, verified unchanged) across 4 icon redesigns + content overhaul. With pure cache-first + `skipWaiting()`, returning **PWA** users are pinned to a stale shell forever. Web-path only; does **not** block the iOS submission.
3. **P1 — Data mis-resolution: 13 artists at "642 Moulton Avenue" plot in the NORTH row** (~581px off). The bare POSITIONS key (`index.html:1331`, y:112) is geographically wrong; the correct south West/East shapes (`:1297-1298`, y:616) get 0 artists. Verified. Claude-fixable.
4. **P2 cluster (Claude-fixable):** bundle id `com.breweryartwalk.app` still embeds the mark (owner-deferred); sub-unit resolver ignores unit letter (3 artists on wrong micro-cell); in-app Privacy/Support links 404 vs published `.html` permalinks (verified); `05-nearme.png` screenshot shows the iOS "localhost" location dialog; no CSP meta; dark-theme `.bld-street` contrast failure (2.88:1); search input has no programmatic label.

**Regression introduced by the remediation pass:** one — the **stale committed iOS `public/` bundle** (`ios/App/App/public/index.html`, 194 KB pre-strip vs the 177 KB facts-only `www/`). It is gitignored and auto-regenerated by `npm run ios:sync`, so it is a build-hygiene gate (run `cap sync` before Archive), not a shipped defect; adversarial review downgraded it P1→P2 and corrected the "still contains bios/photos" claim to "the leftover is the scraped `category_original` field," since the bio/image values were already empty.

**What is solid:** geolocation projection is mathematically self-consistent (forward/inverse round-trip to identity); zero third-party/CDN/network dependencies in the shipped HTML (self-hosted font, inlined data); UX layer ships with no P0/P1 defects and the removed "Take me there" route is gone end-to-end (0 grep hits); `prepare.js` is idempotent and the `www/` mirror is byte-identical; the App Store metadata, privacy questionnaire, and proactive 5.2 review note are honest and aligned. ### P1 — Copyrighted official map + 197 scraped artist photos persist in git history on a PUBLIC remote — *CONFIRMED*
- **Location:** git history of `origin https://github.com/Mattkillsyou/ArtWalk.git`, branch `main` @ `6d26dfe`; blobs `Map.jpg` (1.7 MB), `map_greyscale.jpg`, `bw map.jpg`, `template.svg` (~593 KB), `template-shapes.json`, `image00001.jpeg` (4.4 MB), `IMG_1075 copy.png` (8.7 MB), `IMG_1077 copy.png` (7.1 MB), `ocr.json`, and `img/artists/**` (exactly 197 photos).
- **Reality (post-verification):** Independently re-confirmed `git rev-parse HEAD == origin/main == 6d26dfe` and `git remote -v` is the public GitHub repo, so local `main` has been pushed. `git rev-list origin/main --objects | grep` returns all the unlicensed map artwork + 197 photos. **The shipped artifact is clean** — 0 of these blobs are tracked under `www/` or `ios/App/App/public/`, so the App Store binary does **not** contain them. The exposure is solely the public repo *history*: the working-tree delete and `.gitignore` do not rewrite history.
- **Recommendation (HUMAN-ONLY):** Treat as a release blocker for making the repo public. (1) Keep the GitHub repo **private** until scrubbed; (2) rewrite history with `git filter-repo --invert-paths` / BFG to purge `Map*.jpg`, `bw map.jpg`, `map_greyscale.jpg`, `template.svg`, `template-shapes.json`, `image00001.jpeg`, `IMG_10* copy.png`, `ocr.json`, `img/artists/**`, then force-push (the one CLAUDE.md-sanctioned force-push exception) and have any clones re-clone; or (3) delete + recreate the repo from a squashed HEAD snapshot. **Do not attempt unattended.** This scrub also reclaims most of the 61 MB `.git`.

### P1 — Service-worker cache version `studiomap-shell-v1` never bumped → stale shell for returning PWA users — *CONFIRMED*
- **Location:** `sw.js:9` (`const CACHE = 'studiomap-shell-v1'`); install precaches `SHELL=['./','./index.html']` (`sw.js:10-19`); cache-first read (`sw.js:38-48`); registration gated to http(s) at `index.html:1263`.
- **Reality (post-verification):** Re-confirmed `sw.js:9` is still `v1` (identical in `www/sw.js`); `git log -S` shows it last changed at commit `926eae4`, with 31 commits since (incl. 4 icon redesigns, content strip, font self-hosting). `activate` deletes only caches `!== CACHE`, so with the name unchanged it purges nothing; `./` and `./index.html` are precached, so `caches.match` always hits and the fresh shell is never fetched. `skipWaiting()` + `clients.claim()` make the stale SW take control immediately → a returning GitHub Pages PWA user gets the outdated app indefinitely with no update path. **First-time visitors (empty cache) get the current shell fine.** The SW is skipped under Capacitor (gated to http(s)), so this is **web/PWA-path only and does NOT block the iOS submission.**
- **Recommendation:** Bump `CACHE` to a content-derived/build-hash version on every release (inject via `prepare.js`), and switch the navigation/`index.html` request to **network-first** (or stale-while-revalidate) so an online user always pulls a fresh shell while staying offline-capable. Add the self-hosted font + icons + manifest to the precache `SHELL` so one online visit guarantees full offline fidelity.

### P1 — 13 artists at "642 Moulton Avenue" plot in the NORTH row, ~581px from the real (south) building — *CONFIRMED*
- **Location:** `index.html:1331` (bare `"642 Moulton Avenue"` x:576/y:112) vs `:1297-1298` (`(West)` x:437/y:616, `(East)` x:475/y:616); `resolvePosKey` `:1376-1397`.
- **Reality (post-verification):** Verified in the live file: the bare key at line 1331 is at **y:112 (north row)** while the real West/East shapes are at **y:616 (south)**. `buildings.json` describes 642 as the "south-center, large L-shaped building" with units E18–E30 / W5–W17, and all 13 artists at this address carry E*/W* units. Because `resolvePosKey` matches the EXACT bare key first, all 13 bucket into the north shape (centroid ~602,173); the geographically-correct south shapes receive 0 artists. This also feeds the wrong lat/lng into "Studios near me" distance sorting for all 13.
- **Recommendation:** Either add a `POS_ALIAS` entry mapping `"642 Moulton Avenue" → "642 Moulton Avenue (West)"` (or split by W*/E* unit prefix), **or** relocate the bare shape's coordinates to the south building. Confirm the canonical footprint against the printed map. Claude-fixable, low blast radius.

### P2 (was P1) — Committed iOS `public/` web bundle is stale (regression) — *PARTIAL (downgraded)*
- **Location:** `ios/App/App/public/index.html` (194,506 B, pre-strip) vs `www/index.html` (177,047 B, facts-only).
- **Reality (post-verification):** Bundles genuinely differ; the iOS copy still has the pre-strip schema. **Correction to the original finding:** it does NOT "still contain images/bios" — the `bio`/`images`/`profile_url` *values* are already empty (that predates this pass); the only substantive leftover is the scraped `category_original` field (108 records) plus the extra key skeleton — a facts-only-policy slip, not a copyrighted-content leak.
