# Handoff — picking up the map refinement on another computer

The campus SVG map is **in-progress**. Building positions are still drifting from the printed `Map.jpg`. The hard work below is calibrating the building footprints to overlay the printed map exactly.

## Quick start (any Mac/Linux/Win box with git + node)

```bash
git clone https://github.com/Mattkillsyou/ArtWalk.git
cd ArtWalk
npm install      # postinstall runs prepare.js (inlines artists.json + buildings.json into index.html)
```

To preview, **any HTTP server works**. Pick one:

```bash
python3 -m http.server 8000
# or
npx serve -l 8000 .
# or just
open index.html       # file:// works for the normal map; overlay mode below needs HTTP
```

Then open **http://localhost:8000/**.

## Editing the map

All map data lives in [`index.html`](index.html):

- **`POSITIONS`** (~line 425): one entry per building. `{ x, y, w, h, short }` — viewBox is `1200 × 1400`. Put `parts: [{x,y,w,h}, …]` on a single building for L-shape / U-shape footprints (see `642 Moulton Avenue`).
- **Streets** (in `renderMap()`, ~line 595): `NORTH MAIN STREET` (top strip), `MOULTON AVE` (diagonal polygon, NW→SE on west side, south end further west than north), `SOUTH AVENUE 21` (right strip).
- **No amenities/icons** — buildings only, by request.

After editing `index.html`, **always run**:

```bash
node prepare.js     # re-inlines JSON and mirrors to www/index.html for Capacitor
```

…then reload the browser.

## The overlay-calibration mode (this is what's still in flight)

Open **http://localhost:8000/?overlay=1** to render the printed `Map.jpg` translucent under the SVG, with building rects drawn as red outlines. Use this to see misalignments and adjust `POSITIONS`.

The image position is controlled by the `OVERLAY` constant in `index.html` (~line 562):

```js
const OVERLAY = { x: -55, y: -490, width: 1310, height: 2300 };
```

These were last tuned by trial-and-error. **They are not yet aligned correctly** — the paper map's title block and footer legend confuse a naive scaling. Tweak `x / y / width / height` until the printed map's `NORTH MAIN STREET` text sits over the SVG's `NORTH MAIN STREET` strip and the printed `MOULTON AVE` road overlays the SVG's diagonal polygon. Once those line up, building rects will jump to wherever they're wrong against the paper, and you can fix them.

When you're done calibrating, the overlay only activates with `?overlay=1` so the production map stays clean.

## State of building positions vs. printed map

What's already correct (verified against the printed map + an OSM/satellite cross-reference):

- `MOULTON AVE` is on the **west** as a diagonal (NW→SE, southwestward).
- `642 Moulton` renders as an actual L-shape (`parts` array).
- `1984 / 2020 / 2100 Atrium` are along the top fronting `North Main`.
- `621 Avenue 21` (orphan from `artists.json`, not in `buildings.json`) is placed on the I-5 Gallery footprint on the east edge.

What's known wrong (per the overlay test):

- The whole campus is **shifted/scaled wrong** relative to the paper. Once `OVERLAY` is calibrated you'll see how much.
- `1910 N. Main` is in the **NW corner** on the printed map (next to the UPS-parking entry arrow), not the SW. My current SVG has it at the SW. **This is wrong** and needs fixing.
- A handful of small buildings (`606`, `608`, `614`, `616`, `674`, `678`, `688`, `694`, `2024 N. Main`) appear on the printed map but are **not in `buildings.json`**. They're skipped. If you want them, add them to `buildings.json` first, then add a `POSITIONS` entry.
